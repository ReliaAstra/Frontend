     1→# Reliastra Frontend & Dashboard Integration Guide
     2→
     3→This guide provides frontend and dashboard developers with complete integration specifications, TypeScript type definitions, exact request/response payloads, and UI patterns for integrating with the **Reliastra External Dependency Intelligence Backend**.
     4→
     5→---
     6→
     7→## 1. Core Integration Concepts
     8→
     9→- **Base URL**: All REST endpoints are prefixed with `/v1`.
    10→  - Local development: `http://localhost:8000/v1`
    11→  - OpenAPI Spec: `http://localhost:8000/openapi.json` (exported locally to `docs/openapi.json`)
    12→  - Swagger UI: `http://localhost:8000/docs`
    13→- **CORS**: The backend is configured via `CORS_ORIGINS` env var. Default: `http://localhost:3000`, `http://localhost:8000`. Set this to your production frontend domain when deploying.
    14→- **Idempotency Header**: For mutation requests (`POST`, `PUT`, `DELETE`), include a unique UUID in the `Idempotency-Key` HTTP header. The backend caches the response in Redis for 24 hours to prevent duplicate submissions on network retries.
    15→- **Error Responses**: Standardized JSON error envelope across all endpoints:
    16→  ```json
    17→  {
    18→    "error": {
    19→      "code": "VALIDATION_ERROR",
    20→      "message": "Input validation failed",
    21→      "details": {
    22→        "errors": [{"loc": ["field"], "msg": "error description"}]
    23→      }
    24→    }
    25→  }
    26→  ```

    30→## 2. Authentication & Session Lifecycle
    31→
    32→The platform supports **Triple Authentication**:
    33→1. **Email/Password** — traditional registration and login with bcrypt-hashed passwords.
    34→2. **Google OAuth 2.0** — one-click sign-up/sign-in via Google account.
    35→3. **GitHub OAuth 2.0** — one-click sign-up/sign-in via GitHub account.
    36→4. **API Keys** (`rel_...`) for automated CI/CD and script integrations.
    37→
    38→All human-facing auth methods (email, Google, GitHub) return the same JWT token pair (`access_token` + `refresh_token`). OAuth flows also return additional user metadata (`is_new_user`, `user_id`, `email`, `full_name`).
    39→
    40→### 2.1 HTTP Authentication Headers
    41→- For user sessions:  
    42→  `Authorization: Bearer <access_token>`
    43→- For API key integrations:  
    44→  `Authorization: ApiKey rel_xxxxxxxxxxxx...`
    45→
    46→### 2.2 Endpoints & Payloads
    47→
    48→#### **POST /v1/auth/register**
    49→Creates a new user account.
    50→```json
    51→// Request Body
    52→{
    53→  "email": "admin@reliastra.dev",
    54→  "password": "SecurePassword123!",
    55→  "full_name": "Jane Doe"
    56→}
    57→
    58→// Response (201 Created)
    59→{
    60→  "user": {
    61→    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    62→    "email": "admin@reliastra.dev",
    63→    "full_name": "Jane Doe",
    64→    "is_active": true
    65→  },
    66→  "access_token": "eyJhbGciOiJIUzI1NiIsIn...",
    67→  "refresh_token": "eyJhbGciOiJIUzI1NiIsIn...",
    68→  "token_type": "bearer",
    69→  "expires_in": 900
    70→}
    71→```
    72→
    73→#### **POST /v1/auth/login**
    74→```json
    75→// Request Body
    76→{
    77→  "email": "admin@reliastra.dev",
    78→  "password": "SecurePassword123!"
    79→}
    80→
    81→// Response (200 OK) -> Same TokenResponse structure as register
    82→```
    83→
    84→#### **POST /v1/auth/refresh**
    85→Rotate tokens transparently when an access token expires (`401 Unauthorized`).
    86→```json
    87→// Request Body
    88→{
    89→  "refresh_token": "eyJhbGciOiJIUzI1NiIsIn..."
    90→}
    91→
    92→// Response (200 OK) -> Returns a new TokenResponse
    93→```
    94→
    95→#### **POST /v1/auth/logout**
    96→Revokes the refresh token in Redis and PostgreSQL.
    97→```json
    98→// Request Body
    99→{
   100→  "refresh_token": "eyJhbGciOiJIUzI1NiIsIn..."
   101→}
   102→// Response (204 No Content — empty body)
   103→```
   104→
   105→### 2.3 Google OAuth 2.0 Flow
   106→
   107→#### **GET /v1/auth/google/url**
   108→Returns the Google OAuth consent screen URL and a CSRF `state` token.
   109→```json
   110→// Response (200 OK)
   111→{
   112→  "authorization_url": "https://accounts.google.com/o/oauth2/v2/auth?client_id=...&scope=openid+email+profile&...",
   113→  "state": "random_csrf_state_token_32_bytes"
   114→}
   115→```
   116→
   117→**Frontend implementation:**
   118→1. Call this endpoint to get the URL and state.
   119→2. Store the `state` in session storage (for CSRF validation).
   120→3. Redirect `window.location.href` to the `authorization_url`.
   121→4. Google redirects back to your `GOOGLE_REDIRECT_URI` with `?code=...&state=...`.
   122→5. Verify the `state` matches, then call `/v1/auth/google` with the code.
   123→
   124→#### **POST /v1/auth/google**
   125→Exchange the Google authorization code for Reliastra JWT tokens.
   126→```json
   127→// Request Body
   128→{
   129→  "code": "4/0AX4XfWg..."
   130→}
   131→
   132→// Response (200 OK)
   133→{
   134→  "access_token": "eyJhbGciOiJIUzI1NiIsIn...",
   135→  "refresh_token": "eyJhbGciOiJIUzI1NiIsIn...",
   136→  "token_type": "bearer",
   137→  "expires_in": 900,
   138→  "is_new_user": true,
   139→  "user_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
   140→  "email": "user@gmail.com",
   141→  "full_name": "John Doe"
   142→}
   143→```
   144→
   145→**Key response fields:**
   146→- `is_new_user`: `true` if this was a first-time Google sign-up (new account created). `false` if the user already existed (sign-in or account link).
   147→- Use `is_new_user` to show a "Welcome! Complete your profile" onboarding flow vs. a direct redirect to the dashboard.
   148→- Store tokens in `localStorage` exactly like email auth (same token format).
   149→
   150→### 2.4 GitHub OAuth 2.0 Flow
   151→
   152→#### **GET /v1/auth/github/url**
   153→Returns the GitHub OAuth authorization URL and a CSRF `state` token.
   154→```json
   155→// Response (200 OK)
   156→{
   157→  "authorization_url": "https://github.com/login/oauth/authorize?client_id=...&scope=read:user+user:email&...",
   158→  "state": "random_csrf_state_token_32_bytes"
   159→}
   160→```
   161→
   162→**Frontend implementation:**
   163→1. Call this endpoint to get the URL and state.
   164→2. Store the `state` in session storage (for CSRF validation).
   165→3. Redirect `window.location.href` to the `authorization_url`.
   166→4. GitHub redirects back to your `GITHUB_REDIRECT_URI` with `?code=...&state=...`.
   167→5. Verify the `state` matches, then call `/v1/auth/github` with the code.
   168→
   169→#### **POST /v1/auth/github**
   170→Exchange the GitHub authorization code for Reliastra JWT tokens.
   171→```json
   172→// Request Body
   173→{
   174→  "code": "a28f3eb5e6b1e7d2c9a0..."
   175→}
   176→
   177→// Response (200 OK)
   178→{
   179→  "access_token": "eyJhbGciOiJIUzI1NiIsIn...",
   180→  "refresh_token": "eyJhbGciOiJIUzI1NiIsIn...",
   181→  "token_type": "bearer",
   182→  "expires_in": 900,
   183→  "is_new_user": true,
   184→  "user_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
   185→  "email": "user@users.noreply.github.com",
   186→  "full_name": "octocat"
   187→}
   188→```
   189→
   190→**GitHub-specific notes:**
   191→- GitHub users can keep their email private. The backend uses a multi-tier resolution: public profile email > primary verified email > any verified email > `login@users.noreply.github.com`.
   192→- If the response email is a `noreply.github.com` address, prompt the user to update their email in account settings.
   193→- The `full_name` field uses the GitHub `name` if available, otherwise falls back to the GitHub `login` (username).
   194→
   195→### 2.5 Email Verification Flow
   196→
   197→New users are created with `is_email_verified=false`. To verify, the frontend triggers the two-step flow below.
   198→
   199→#### **POST /v1/auth/send-verification**
   200→Sends a verification email with a one-time link to the user's inbox. **Rate limited.** All previous unexpired tokens for this user are automatically revoked.
   201→```json
   202→// Request Body
   203→{
   204→  "email": "admin@reliastra.dev"
   205→}
   206→
   207→// Response (200 OK)
   208→{
   209→  "message": "Verification email sent. Check your inbox.",
   210→  "email": "admin@reliastra.dev"
   211→}
   212→
   213→// Error (404) — if no account exists with this email
   214→// Error (400, EMAIL_ALREADY_VERIFIED) — if email is already verified
   215→```
   216→
   217→#### **POST /v1/auth/verify-email**
   218→Consumes the token from the verification link and marks the user's email as verified.
   219→```json
   220→// Request Body
   221→{
   222→  "token": "token_from_email_link"
   223→}
   224→
   225→// Response (200 OK)
   226→{
   227→  "message": "Email verified successfully.",
   228→  "is_email_verified": true
   229→}
   230→
   231→// Error (422, INVALID_TOKEN) — token not found
   232→// Error (422, TOKEN_ALREADY_USED) — token was already consumed
   233→// Error (422, TOKEN_EXPIRED) — token expired (> 60 minutes)
   234→```
   235→
   236→**Frontend implementation:**
   237→1. After registration, show a "Verify your email" banner with a "Resend verification" button.
   238→2. On click, call `POST /v1/auth/send-verification` with the user's email.
   239→3. The email contains a link to `{FRONTEND_BASE_URL}/verify-email?token={token}`.
   240→4. On the verification page, extract the token from the URL query parameter and call `POST /v1/auth/verify-email`.
   241→5. On success, update the user's local state to reflect `is_email_verified: true`.
   242→
   243→### 2.6 Password Reset Flow
   244→
   245→The password reset flow uses anti-enumeration — the same generic message is returned whether or not the email exists in the database, preventing attackers from discovering which emails are registered.
   246→
   247→#### **POST /v1/auth/forgot-password**
   248→Sends a password reset email if an account exists with the given email. **Rate limited.** All previous unexpired tokens for this user are automatically revoked.
   249→```json
   250→// Request Body
   251→{
   252→  "email": "admin@reliastra.dev"
   253→}
   254→
   255→// Response (200 OK) — ALWAYS returns this, even if email doesn't exist
   256→{
   257→  "message": "If an account with this email exists, a password reset link has been sent."
   258→}
   259→```
   260→
   261→#### **POST /v1/auth/reset-password**
   262→Consumes the token from the reset link and sets the new password.
   263→```json
   264→// Request Body
   265→{
   266→  "token": "token_from_email_link",
   267→  "new_password": "NewSecurePassword123!"
   268→}
   269→
   270→// Response (200 OK)
   271→{
   272→  "message": "Password has been reset successfully. You can now log in with your new password."
   273→}
   274→
   275→// Validation Error (422) — password must be at least 8 characters
   276→// Error (422, INVALID_TOKEN) — token not found
   277→// Error (422, TOKEN_ALREADY_USED) — token was already consumed
   278→// Error (422, TOKEN_EXPIRED) — token expired (> 15 minutes)
   279→```
   280→
   281→**Frontend implementation:**
   282→1. On the "Forgot Password" page, collect the email and call `POST /v1/auth/forgot-password`.
   283→2. Always show the success message ("Check your inbox") regardless of the response — do not reveal whether the email exists.
   284→3. The email contains a link to `{FRONTEND_BASE_URL}/reset-password?token={token}`.
   285→4. On the reset password page, extract the token from the URL, collect the new password (with confirmation), and call `POST /v1/auth/reset-password`.
   286→5. On success, redirect to the login page with a success flash message.
   287→
   288→### 2.7 Account Linking Across Providers
   289→
   290→All three auth methods (email, Google, GitHub) are unified by **email address**. If a user registers with `admin@reliastra.dev` via email and later signs in with Google using the same email, the Google identity is linked to the existing account — no duplicate is created. The same applies for GitHub.
   291→
   292→**Frontend UX recommendations:**
   293→- On the login page, show "Continue with Google" and "Continue with GitHub" buttons alongside the email/password form.
   294→- After OAuth redirect, check `is_new_user` to route to either onboarding or dashboard.
   295→- In account settings, display the user's linked providers (show badges for Google, GitHub, Email).

   554→| Parameter   | Type   | Default | Description                                                         |

   556→| `window`    | string | `24h`   | Time window. Supported: `1h`, `6h`, `24h`, `7d`, `30d`, `90d`.    |
   557→| `resolution`| string | `auto`  | Bucket resolution. Supported: `auto`, `1m`, `5m`, `15m`, `1h`, `6h`. |
   558→| `region`    | string | `us-east-1` | Probe region filter. Currently `us-east-1`. Schema supports future multi-region. |
   559→
   560→#### Auto-Resolution Defaults
   561→
   562→| Window | Auto Resolution |
   563→|--------|----------------|
   564→| `1h`   | `1m`           |

   567→| `7d`   | `15m`          |
   568→| `30d`  | `1h`           |

   608→#### Field Reference
   609→
   610→| Field              | Type               | Description                                                    |
   611→|--------------------|--------------------|----------------------------------------------------------------|
   612→| `vendor_name`      | string             | Vendor slug identifier.                                        |
   613→| `window`           | string             | Requested time window (e.g. `24h`).                            |
   614→| `resolution`       | string             | Resolved bucket resolution (human-readable when `auto`).       |
   615→| `region`           | string             | Probe region used for observations.                            |
   616→| `from`             | ISO 8601 datetime  | Window start time (UTC).                                       |
   617→| `to`               | ISO 8601 datetime  | Window end time (UTC).                                         |
   618→| `current`          | object             | Most recent observation, independent of the window.            |
   619→| `current.timestamp`| ISO 8601 datetime  | Time of the latest observation (`null` if none).              |
   620→| `current.latency_ms`| float \| null     | Latency of the latest observation (`null` if none).           |
   621→| `current.status_code`| int \| null       | HTTP status code (`null` if no observation).                   |
   622→| `current.is_up`    | bool \| null       | `true` if the latest observation has a valid status code and no errors. |
   623→| `points`           | array              | Aggregated time buckets, ordered chronologically.              |
   624→| `points[].timestamp`| ISO 8601 datetime  | Bucket start time (UTC).                                       |
   625→| `points[].avg_latency_ms`| float         | Average latency across observations in this bucket.           |
   626→| `points[].status_code`| int \| null       | Representative status code for the bucket.                    |
   627→| `points[].is_up`    | bool              | `true` if ALL observations in the bucket are healthy.         |
   628→| `points[].observation_count`| int          | Number of raw observations in this bucket.                      |
   629→| `points[].incident_id`| UUID \| null     | Incident ID if this bucket overlaps an active incident.        |
   630→
   631→#### Frontend Rendering Guide
   632→
   633→The `points` array is designed for direct rendering into three visual layers:
   634→
   635→1. **Latency Graph** — Plot `points[].avg_latency_ms` on the Y-axis against `points[].timestamp` on the X-axis. Use `observation_count` to indicate data density (thicker line or opacity for higher counts).
   636→
   637→2. **Availability Graph** — Plot `points[].is_up` as a binary state (1/0) or as a colored background band. Green for `is_up: true`, red for `is_up: false`.
   638→
   639→3. **Incident Markers** — For any point where `incident_id` is not `null`, render a visible marker (e.g., vertical line, shaded region, or icon) on the timeline. Cross-reference with the `/incidents` endpoint for incident details.
   640→
   641→#### Polling Recommendation
   642→
   643→- **Poll interval**: 15–30 seconds for the `1h` or `6h` window.
   644→- **Recommended default**: `GET /v1/public/vendors/stripe/timeline?window=1h&resolution=1m`
   645→- **Use `current` for live display**: Show "Observed X seconds ago" by computing `Date.now() - new Date(current.timestamp)`.
   646→- **Do not use WebSocket/SSE** for this endpoint in the current version. Polling is sufficient and simpler.
   647→- The response is cached server-side with shorter TTLs for recent windows. Do not poll faster than every 10 seconds.
   648→
   649→#### Error Responses
   650→
   651→| Status | Code                  | When                                |
   652→|--------|-----------------------|-------------------------------------|
   653→| 404    | `RESOURCE_NOT_FOUND`  | Vendor not found or not public.     |
   654→| 422    | `VALIDATION_ERROR`    | Invalid `window` or `resolution`.   |
   655→| 429    | `RATE_LIMIT_EXCEEDED` | Public vendor rate limit exceeded.  |

   749→## 11. TypeScript Integration Reference & Axios Client Wrapper
   750→
   751→Copy and paste this TypeScript API client wrapper into your frontend project (`src/lib/api.ts`):
   752→
   753→```typescript
   754→import axios, { AxiosError, InternalAxiosRequestConfig } from "axios";
   755→
   756→export const API_BASE_URL = process.env.NEXT_PUBLIC_API_URL || "http://localhost:8000/v1";
   757→
   758→export const apiClient = axios.create({
   759→  baseURL: API_BASE_URL,
   760→  headers: {
   761→    "Content-Type": "application/json",
   762→  },
   763→  timeout: 10000,
   764→});
   765→
   766→// Request Interceptor: Attach access token & idempotency keys
   767→apiClient.interceptors.request.use((config: InternalAxiosRequestConfig) => {
   768→  const token = localStorage.getItem("reliastra_access_token");
   769→  if (token && config.headers) {
   770→    config.headers.Authorization = `Bearer ${token}`;
   771→  }
   772→
   773→  // Attach idempotency key for mutations
   774→  if (["post", "put", "delete", "patch"].includes(config.method || "")) {
   775→    config.headers["Idempotency-Key"] = crypto.randomUUID();
   776→  }
   777→  return config;
   778→});
   779→
   780→// Response Interceptor: Silent token rotation on 401
   781→apiClient.interceptors.response.use(
   782→  (response) => response,
   783→  async (error: AxiosError) => {
   784→    const originalRequest = error.config as InternalAxiosRequestConfig & { _retry?: boolean };
   785→
   786→    if (error.response?.status === 401 && !originalRequest._retry) {
   787→      originalRequest._retry = true;
   788→      const refreshToken = localStorage.getItem("reliastra_refresh_token");
   789→
   790→      if (refreshToken) {
   791→        try {
   792→          const { data } = await axios.post(`${API_BASE_URL}/auth/refresh`, {
   793→            refresh_token: refreshToken,
   794→          });
   795→          localStorage.setItem("reliastra_access_token", data.access_token);
   796→          if (data.refresh_token) {
   797→            localStorage.setItem("reliastra_refresh_token", data.refresh_token);
   798→          }
   799→          if (originalRequest.headers) {
   800→            originalRequest.headers.Authorization = `Bearer ${data.access_token}`;
   801→          }
   802→          return apiClient(originalRequest);
   803→        } catch (refreshError) {
   804→          localStorage.removeItem("reliastra_access_token");
   805→          localStorage.removeItem("reliastra_refresh_token");
   806→          window.location.href = "/login";
   807→        }
   808→      }
   809→    }
   810→    return Promise.reject(error);
   811→  }
   812→);
   813→```

   872→  const { data } = await apiClient.get<OAuthUrlResponse>("/auth/google/url");
   873→  return data;
   874→};

   876→export const exchangeGoogleCode = async (code: string): Promise<OAuthCallbackResponse> => {
   877→  const { data } = await apiClient.post<OAuthCallbackResponse>("/auth/google", { code });
   878→  return data;
   879→};
   880→
   881→/** Initiates Google OAuth flow: stores state, redirects to Google consent screen. */
   882→export const initiateGoogleLogin = async () => {
   883→  const { authorization_url, state } = await getGoogleAuthUrl();
   884→  sessionStorage.setItem("google_oauth_state", state);
   885→  window.location.href = authorization_url;
   886→};
   887→
   888→/** Handles Google OAuth callback: extracts code, exchanges for tokens. */
   889→export const handleGoogleCallback = async () => {
   890→  const params = new URLSearchParams(window.location.search);
   891→  const code = params.get("code");
   892→  const returnedState = params.get("state");
   893→  const savedState = sessionStorage.getItem("google_oauth_state");
   894→
   895→  if (!code) throw new Error("No authorization code received from Google");
   896→  if (returnedState !== savedState) throw new Error("OAuth state mismatch — possible CSRF");
   897→
   898→  sessionStorage.removeItem("google_oauth_state");
   899→  return await exchangeGoogleCode(code);
   900→};

  1109→```typescript
  1110→"use client";
  1111→
  1112→import { useEffect, useState, FormEvent } from "react";
  1113→import { useRouter, useSearchParams } from "next/navigation";
  1114→import { resetPassword } from "@/services/emailAuthService";
  1115→
  1116→export default function ResetPasswordPage() {
  1117→  const router = useRouter();
  1118→  const searchParams = useSearchParams();
  1119→  const [status, setStatus] = useState<"loading" | "form" | "success" | "error">("loading");
  1120→  const [errorMsg, setErrorMsg] = useState("");
  1121→  const [password, setPassword] = useState("");
  1122→  const [confirmPassword, setConfirmPassword] = useState("");
  1123→
  1124→  useEffect(() => {
  1125→    // If there's no token, show the "forgot password" entry point instead
  1126→    const token = searchParams.get("token");
  1127→    if (token) {
  1128→      setStatus("form");
  1129→    } else {
  1130→      router.push("/forgot-password");
  1131→    }
  1132→  }, [searchParams, router]);
  1133→
  1134→  const handleSubmit = async (e: FormEvent) => {
  1135→    e.preventDefault();
  1136→
  1137→    if (password.length < 8) {
  1138→      setErrorMsg("Password must be at least 8 characters long.");
  1139→      return;
  1140→    }
  1141→    if (password !== confirmPassword) {
  1142→      setErrorMsg("Passwords do not match.");
  1143→      return;
  1144→    }
  1145→
  1146→    try {
  1147→      const token = searchParams.get("token")!;
  1148→      await resetPassword(token, password);
  1149→      setStatus("success");
  1150→      setTimeout(() => router.push("/login?reset=success"), 2000);
  1151→    } catch (error: any) {
  1152→      setStatus("error");
  1153→      setErrorMsg(error?.response?.data?.error?.message || "Failed to reset password. The link may have expired.");
  1154→    }
  1155→  };
  1156→
  1157→  if (status === "loading") {
  1158→    return <div className="flex items-center justify-center min-h-screen"><p className="text-gray-500">Loading...</p></div>;
  1159→  }
  1160→
  1161→  if (status === "success") {
  1162→    return (
  1163→      <div className="flex items-center justify-center min-h-screen">
  1164→        <div className="text-center">
  1165→          <p className="text-green-600 font-medium">Password reset successfully!</p>
  1166→          <p className="text-gray-400 text-sm mt-1">Redirecting to login...</p>
  1167→        </div>
  1168→      </div>
  1169→    );
  1170→  }
  1171→
  1172→  return (
  1173→    <div className="flex items-center justify-center min-h-screen">
  1174→      <form onSubmit={handleSubmit} className="w-full max-w-sm space-y-4 p-6 bg-white rounded-lg shadow-md">
  1175→        <h2 className="text-xl font-semibold text-center">Set New Password</h2>
  1176→
  1177→        {status === "error" && (
  1178→          <p className="text-red-500 text-sm text-center">{errorMsg}</p>
  1179→        )}
  1180→
  1181→        <input
  1182→          type="password"
  1183→          placeholder="New password (min. 8 characters)"
  1184→          value={password}
  1185→          onChange={(e) => setPassword(e.target.value)}
  1186→          className="w-full px-3 py-2 border rounded-md"
  1187→          minLength={8}
  1188→          required
  1189→        />
  1190→
  1191→        <input
  1192→          type="password"
  1193→          placeholder="Confirm new password"
  1194→          value={confirmPassword}
  1195→          onChange={(e) => setConfirmPassword(e.target.value)}
  1196→          className="w-full px-3 py-2 border rounded-md"
  1197→          minLength={8}
  1198→          required
  1199→        />
  1200→
  1201→        <button
  1202→          type="submit"
  1203→          className="w-full py-2 bg-blue-600 text-white rounded-md hover:bg-blue-700"
  1204→        >
  1205→          Reset Password
  1206→        </button>
  1207→      </form>
  1208→    </div>
  1209→  );
  1210→}
  1211→```
